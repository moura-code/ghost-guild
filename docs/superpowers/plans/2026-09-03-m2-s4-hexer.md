# M2 Stage 4 — The Hexer

Spec §3.4, §5.6, §7. The second class, and the first choice the player makes
about who they are rather than about what they buy.

## Why this, now

The spec's launch scope is two classes. There is one, and every run since the
game existed has been the same ten cards in the same order. A roguelite whose
runs all open identically has no second session.

It is also the thing the last stage earned. §5.6: the Hexer is "unlocked by the
first true ghost in Fungal Deep" — the Deep exists now, claims are derived from
the ladder, and the unlock is one line away from being real. Shipping the biome
and not the thing it unlocks would leave the claim mechanic with exactly one
consequence.

And it is the same shape of risk the biome stage was. The game has had one
class for its entire life. `Ghost.founder` reads `content.classes["sexton"]`
by name. `Expeditions.hero_for` falls back to `"sexton"`. `CampaignEngine.new_hero`
hardcodes it. Those are correct exactly as long as there is one class, and the
only way to find the rest is to add a second.

## What the Hexer is

Poison and Weak — attrition (§3.4). Where the Sexton blocks and hits, the Hexer
survives by making the enemy worse at hitting and by damage that has already
happened by the time the turn ends.

Mechanically that means the class must **not** be a Sexton with different card
names, and the same test the Fungal Deep uses applies here: a Hexer deck and a
Sexton deck must diverge measurably, in opposite directions, between the two
biomes. The Sexton should still be the better Catacombs class (Holy ×1.5 into
Undead, and its Bone cards are direct damage); the Hexer should be the better
Deep class (Poison ×1.5 into Flesh). That is what makes the unlock a reward
rather than an upgrade.

Lower HP than the Sexton, and worse block, or "attrition" is free.

## Batches

### Batch A — a class is a thing you can have more than one of

**Files:** `core/content/class_def.gd`, `core/content/classes.gd` (new),
`core/campaign_engine.gd`, `core/ghosts/ghost.gd`, `core/economy/expeditions.gd`,
`core/economy/balance_sim.gd`, `tools/`, tests.

`ClassDef.unlocked_by` names a biome, or is empty for a class you start with.
`Classes.unlocked(content, ladder)` returns the ids available, derived from the
claim the way `Biomes.claimed` is — a stored unlock can disagree with the
ladder and the ladder is the truth.

`CampaignEngine.new_hero(c, now, class_id)` takes the class. `Ghost.founder`
takes the starting class from the data rather than from a string literal:
"the class with no `unlocked_by`" is a rule, `"sexton"` is a hardcoded fact
that happens to be true today.

No new content in this batch, so every demo must be byte-identical.

### Batch B — the Hexer exists

**Files:** `data/classes/hexer.json`, `data/cards/hexer.json` (new),
`data/relics/`, `data/strings/en.csv`, icons, tests.

Three basics (the Hexer's own strike/defend/opener), twelve pool cards, a class
relic, a class icon, card art. Lower base HP than the Sexton.

The mechanical guard, measured rather than asserted: **the Sexton must win more
in the Catacombs and the Hexer must win more in the Deep**, with the same seed
and the same number of fights. If both classes prefer the same biome, one of
them is strictly worse and the unlock is not a choice.

### Batch C — you choose who goes down

**Files:** `game/hud/hero_screen.gd`, `game/game.gd`, `core/campaign_engine.gd`,
`data/strings/en.csv`, tests, one rendered shot.

A hero who has never descended can be re-made as any unlocked class, at the
desk, before the run starts. `hero.runs == 0` is the gate: every death hands
you a fresh hero, so every death is a class choice, and nobody swaps class
halfway through a campaign to dodge a bad matchup.

Locked classes are shown, not hidden — a class you cannot pick yet, with the
reason next to it, is the whole point of an unlock. The Kiln's class will slot
into the same list on the day it exists.

## Self-review

The risk in Batch A is the same silent one as last stage: the class system has
never had to be a system. The check is again the demos plus a test that the
starting class is derived from the data rather than named.

The risk in Batch B is that the Hexer is a reskin. The guard is the crossed
comparison — Sexton better upstairs, Hexer better downstairs — which fails
loudly if the two classes converge, and which no amount of card-naming can fake.

The risk in Batch C is a class swap that loses something. It cannot: the gate
is a hero who has never descended, so the only state discarded is a deck that
has never been played. Reach, upgrades, Soul, the ladder and the camp are all
campaign-level and untouched.

## Executed

All three batches.

### Batch A — a class became a system

`ClassDef.unlocked_by`, `Classes.starting/unlocked/is_unlocked/locked_behind`.
The starting class is the class nothing has to be unlocked for, which is a rule
the data states; `"sexton"` was a hardcoded fact in `Ghost.founder`,
`CampaignEngine.new_hero`, `Expeditions.hero_for`, `balance_sim`, `run_demo`
and `fight_demo`, and it happened to be true. All six read the rule now.

### Batch B — the Hexer, tuned by measurement rather than by intention

Three basics, twelve pool cards, a relic, sixteen icons.

The first cut was **strictly better than the Sexton at every depth** — +0.08 at
floor 8, +0.23 at 10, +0.45 at 18, and faster (5.4 turns against 7.2). That is
the failure mode the plan named, and the crossed test caught it on the first
run. Three things were doing it: the Thimble gave 2 Weak to all enemies every
fight, which is strong against everything; the class opened with a free point
of Wit; and `ill_wish` stacked Weak *and* Vulnerable for one energy.

The fix that made the class a choice rather than an upgrade was to make its
relic **biome-sensitive by construction**: the Thimble applies Poison, not
Weak, and Poison is ×1.5 into Flesh and ×1.0 into Undead. So the relic is worth
more in the biome that unlocks the class, which is what the unlock is supposed
to mean. Wit went back to zero and `ill_wish` lost the Vulnerable.

Measured after:

| floor | 5 | 8 | 10 | 12 | 14 | 16 | 18 |
|---|---|---|---|---|---|---|---|
| Sexton | 1.00 | 0.92 | 0.75 | 0.67 | 0.40 | 0.40 | 0.00 |
| Hexer | 1.00 | 0.82 | 0.75 | 1.00 | 0.72 | 0.62 | 0.25 |

Sexton ahead in the Catacombs, Hexer ahead in the Deep, level at the boss
floor between them. `test_each_class_is_the_better_one_somewhere` asserts both
halves; either one flipping fails it.

**Class relics are now excluded from relic drops.** Adding a seventh relic to
the pool would have offered a Sexton the Hexer's Thimble — another class's
identity as loot — and would have broken demo byte-identity into the bargain.
Derived from the classes rather than flagged in the relic data, so the two
cannot drift.

### Batch C — the choice

`CampaignEngine.choose_class` and `GameRoot.choose_class`, gated on
`hero.runs == 0`: every death hands you a fresh hero, so every death is a class
choice, and nobody swaps mid-campaign to dodge a matchup. Nothing is lost by
it — reach, Soul, upgrades, the ladder and the camp are campaign-level, and the
camp is carried across explicitly because it is where the *guild* got to, not
where this deck did.

The row shows every class in the data, locked ones greyed with the biome that
opens them on the tooltip. A reward you cannot see is not a reward.

### What rendering found: the game is not wearing its own theme

`UiTheme.build()` **is never applied to the running game.** It is constructed
only in tests. Measured on a live `HudRoot`:

```
label    font=Open Sans SemiBold size=8   height=12.0
button   font=Open Sans SemiBold size=16  height=23.0
```

Two consequences, both visible in every screenshot in `docs/shots/review/` once
you know to look:

1. **The bundled fonts are almost unused.** Only `UiTheme.title()` and
   `TurnBanner` call `add_theme_font_override`. Everything else — body, small,
   numbers, every button — renders in Godot's default Open Sans at the right
   *size*. Silkscreen and PixelifySans are in the build and on two labels.
2. **The carved `StoneBox` theme is unused.** Every `Button`, `PanelContainer`
   and scrollbar stylebox in `build()` is dead. The screens that look carved —
   the upgrade tablets, the expedition band, now the class row — are the ones
   whose authors called `add_theme_stylebox_override` by hand. Everything else
   is a stock Godot control.

Not fixed here, deliberately. It is one line in `HudRoot`, and then every
layout constant in the game has to be re-checked: `UpgradePlaque.PLAQUE_SIZE`,
`ExpeditionLine.HEIGHT`, `RulePicker.CELL`, the card sizes and every panel
width were all tuned by eye against Open Sans metrics. Applying the theme
without that pass would trade a wrong font for a broken layout. **This is the
next stage**, and it is probably the highest-value one left for how the game
looks.

The class row is styled by hand in the meantime, so it matches the tablets
rather than adding another stock control.

### Notes for later

- The Sexton's starting deck contains no Holy card, so its Catacombs advantage
  comes from block and raw damage rather than from the affinity table. Tagging
  `last_rites` Holy would sharpen the contrast and would change the demos, so
  it belongs in the balance pass with everything else that moves those numbers.
