# M1-C2 — The Run Side Implementation Plan

**Goal:** Make Ghost Guild playable. Take a hero down into the Catacombs, fight card by card, choose where to die, and watch the ghost slide into the tower — the loop the whole design hangs on.

**Architecture:** Same as M1-C1. `core/` is frozen and has no scene tree; `GameRoot` is the only bridge and the only place that mutates the campaign; screens are `Control` subclasses built in GDScript and take their `GameRoot` through `bind(g)`. The run adds one thing C1 did not have: **an event stream to animate from.** `CombatEngine.apply(state, action)` returns the events it produced — `damage`, `block_gained`, `card_played`, `enemy_died`, `status_applied` and twenty-odd more — and the fight screen renders those events rather than diffing state. That is what makes juice cheap.

**Tech Stack:** Godot 4.7.2, GDScript with static typing, GdUnit4. No art assets: colour, typography, `Control._draw()` and `Tween`.

**Spec:** `docs/superpowers/specs/2026-08-21-ghost-guild-design.md` (v2) — §3.2 (a run), §3.4 (onboarding), §4 (combat), §9 (UI), §11 (M1 scope). Binding authority.

**Execution:** Inline, in the main session — not subagent-driven. Joao asked for this on 2026-08-24 because the dispatch round trips cost too much wall clock. Consequences for this document: it is a **design and task plan, not a code transcript**. It does not carry verbatim implementations, because the person implementing it wrote it and has the context. What it does carry is the architecture, the task order, the interfaces between tasks, the test strategy, and the decisions already made — everything that would otherwise get re-litigated halfway through.

**What survives from the subagent discipline:** a real failing test before every implementation; verification by running commands, never by asserting; reading my own diff before committing; and a ledger of rulings in `docs/superpowers/plans/m1c2-rulings.md` so the calls made on Joao's behalf are visible and reversible.

## Starting State

`main` at the M1-C1 merge: **341 GdUnit4 tests, all green.** The game launches and the idle half works — Ladder, Guild, Séance, Hero, offline summary, save-on-quit. `game/main.gd` routes four tabs. There is no way to start a run.

Known debt to respect: `docs/superpowers/deferred-items.md`, in particular the **accrue-then-mutate rule** (settle production before any mutation) and the **threading note** (a 50-fight simulation costs 300 ms–3 s, so the exit screen's numbers must not block the frame).

## Global Constraints

Everything from M1-C1 still binds. Restated because they are load-bearing:

- **Nothing under `core/` changes.** If a task appears to need it, that is a plan defect — stop and rule on it.
- Static typing everywhere. `round`/`floor`/`abs`/`max`/`min` return `Variant` and break `:=` — use `roundf`/`floorf`/`absf`/`maxf`/`maxi`/`minf`/`mini`. Iterating a `Dictionary` yields `Variant` too.
- Player-facing strings via `game.text(key)` against `data/strings/en.csv`. Colours from `Palette`. Numbers through `Num`.
- Screens receive `GameRoot` via `bind(g)`; only `MainScreen` touches the `/root/Game` autoload. Widgets take data through `bind()` and never touch `Game`.
- Every campaign mutation goes through a `GameRoot` wrapper that settles production first.
- **New for this plan:** the fight screen renders the **event stream**, not state diffs. `CombatEngine.apply` returns the events an action produced; hand them to the animator. State is the source of truth for what is on screen; events are the source of truth for what just happened.
- **New:** no simulation on the UI thread. `RunEngine.exit_summary` runs a survival projection that can cost seconds. It goes on `WorkerThreadPool`, with the screen showing a pending state until it lands.
- Commit `.gd.uid` sidecars. Trailer: `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`

## Core API this plan builds on

Read once; every task uses it.

**`RunEngine`** — `start_run(content, hero, biome_id, entry_floor, run_seed, watch_unlocked) -> RunState`; `legal_actions(run) -> Array`; `apply(run, action) -> Array` (the events produced); `exit_summary(run, samples := -1) -> {floor, measured, next_floor, survival, can_push, can_retreat, can_watch}`; `can_push(run)`, `can_watch(run)`.

**`RunState`** — `phase` is the router key: `descent`, `node`, `fight`, `reward`, `event`, `rest`, `shop`, `exit`. Plus `floor`, `nodes`, `node_index`, `fight`, `coin`, `soul`, `descent_offers`, `reward`, `shop`, `event_id`, `outcome`, `is_over()`, `current_node()`.

**Actions by phase** (from `legal_actions`): `descent` → `draft_pick{card}` / `draft_skip`; `node` → `enter`; `fight` → `play{hand_index, target}` / `end_turn`; `reward` → `take_card{card}` / `skip_card`; `event` → `choose{index}`; `rest` → `rest_heal` / `rest_upgrade{uid}`; `shop` → `buy_card{card}` / `buy_relic` / `remove_card{uid}` / `leave`; `exit` → `push` / `retreat` / `watch`.

**`FightState`** — `turn`, `phase`, `hero_hp`, `hero_max_hp`, `hero_block`, `energy`, `max_energy`, `statuses`, `hand`, `draw_pile`, `discard_pile`, `exhaust_pile`, `enemies: Array[EnemyState]`, `living_enemy_indices()`, `is_over()`. `EnemyState` — `def_id`, `hp`, `max_hp`, `block`, `statuses`, `next_move`, `alive`.

**Fight events worth animating** — `damage{target, amount, source}`, `block_gained`, `heal`, `card_played`, `card_drawn`, `card_discarded`, `card_exhausted`, `status_applied`, `status_tick`, `enemy_intent`, `enemy_move`, `enemy_died`, `turn_start`, `turn_end`, `energy_changed`, `reshuffle`, `relic_triggered`, `fight_won`, `fight_lost`.

**`CampaignEngine`** — `start_run(c, entry_floor, now) -> RunState` (validates entry against reach, refuses an unbanked finished run), `finish_run(c, now) -> {kind, floor, soul, ghost_id, epitaph, new_hero, rite_events}`, `reach(c) -> int`.

## Task Order

Ordered so the game becomes playable as early as possible, and so each task ends somewhere you can stop.

### Task 1 — Descend, and the run routes itself
`GameRoot` gains `start_run(entry_floor)` and `finish_run()` (settling first, saving after) plus a `run_changed` signal. `MainScreen` shows a `RunView` instead of the tabs whenever `campaign.run != null`. `RunView` maps `phase` to a placeholder panel per phase and applies the single legal action for phases with one. The Ladder gets a **Descend** button, and the "not in this build" line comes out.

Fights in this task resolve through `RunAutopilot` — you press Descend and watch a run play out to its end, then the epitaph result lands and a ghost appears on the tower.
**Stop-here value:** the whole loop is visible end to end for the first time.

### Task 2 — The floor map
`floor_map_screen.gd`: the floor's three nodes plus the exit drawn as a path, kinds distinguished typographically, the current node lit and clickable. Replaces the auto-`enter`.

### Task 3 — The fight screen, playable
`card_view.gd`, `enemy_view.gd`, `hero_panel.gd`, `fight_screen.gd`. Enemies across the top with HP and telegraphed intent; hero bottom-left with HP, block, energy; hand along the bottom; pile counts in the corners. Click a card, click a target, end turn. No animation yet — correctness first.
**Stop-here value: the game is playable by hand.**

### Task 4 — Juice
`float_number.gd` and `fight_animator.gd`. The event stream drives floating damage, card tween on play, hit-stop on a big hit, screen shake scaled to damage, block shimmer, enemy death fade, `CPUParticles2D` on impact. Numbers count rather than snap. This is the task that decides whether the game feels alive, and it is not optional polish.

### Task 5 — Reward, rest, shop, event
The four non-fight nodes in one file. Card rewards after every fight are what keep the starter deck from being a slog (§3.4).

### Task 6 — The exit decision
The three numbers §9 says the player learns to read: yield here (measured), yield next floor (simulated), survival chance. Push / Retreat / Take the Watch. **The projection runs on `WorkerThreadPool`** with a pending state — this is where §11's "under 100 ms" criterion bites.

### Task 7 — The epitaph moment
Full screen. The name, the floor, the epitaph, the ghost sliding into its row on the tower, the number starting to tick. §9 calls this the emotional beat and the trailer opening — give it time and deliberate pacing. Death is not a failure dialog.

### Task 8 — The Descent draft
Pick-of-three per skipped floor when entering below your reach, and the entry-floor picker on the Descent screen.

## Test Strategy

Screens are tested the way C1's were: instantiate with an injected `GameRoot`, `add_child`, `await await_idle_frame()`, assert on bound state and on what a click does. Three rules learned the hard way on C1:

1. **Every test must be able to fail.** C1 shipped a deck test that passed with the feature deleted. Before committing a test, ask what breaking would make it red — and if the answer is "nothing", rewrite it.
2. **Verify engine side effects rather than assuming them.** Godot's `Range` silently re-clamps `.value` when you set `min_value`, which defeated a guard and would have placed ghosts on the wrong floor. When behaviour depends on an engine side effect, prove it.
3. **Animation is tested for state, not for pixels.** Assert that an event produces a `FloatNumber` with the right text and that it frees itself; do not assert tween interpolation.

## Definition of Done

`& $env:GODOT_BIN --path .` opens the game; you press Descend, walk a floor, fight a real fight by hand, read the exit numbers, choose to push or take the watch, see the epitaph, and find your ghost standing on the tower earning Soul. The suite is green and `tools/balance_sim.gd`'s two open findings are unchanged (they are content tuning, tracked separately in `deferred-items.md`).
